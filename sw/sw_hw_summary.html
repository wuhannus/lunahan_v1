3. Pipeline Hazard Model (Critical for SW Performance)

HazardExamplePenaltySoftware Mitigation
Load-use stalllw t0,0(a0); add t1,t0,t21 cycleSchedule independent instruction between load and use
Branch mispredictBTB miss / wrong direction2 cyclesAlign branch targets to 16B (I$ line); use likely direction
MUL stallmul t0,t1,t23 cyclesSchedule independent work after MUL; use shifts for ×2/×4
DIV stalldiv t0,t1,t231 cyclesAvoid division in hot paths; use reciprocal multiply
I$ missSequential / jump4-8 cyclesKeep hot loops < 4KB; align functions to 16B; use C extension
D$ missWrite-back / read miss4-8 cyclesPack structs; prefetch; avoid random access patterns

4. Forwarding Paths (Exploit These!)

PathLatencyOptimal Code Pattern
EX → EX0 cycles (fwd)add t0,t1,t2; sub t3,t0,t4 — back-to-back OK
MEM → EX0 cycles (fwd)lw t0,0(a0); nop; add t1,t0,t2 — need 1 NOP gap
WB → EXNever neededForwarding captures value earlier in pipeline

Rule: Separate load and ALU-use by at least 1 instruction. ALU→ALU chains have zero stall cost due to forwarding.

5. Compiler Tuning (sw/tuning.mk)

FlagEffect on lunahan_v1
-march=rv32imcRV32I base + Multiply + Compressed. C extension reduces I$ pressure by ~30%
-mabi=ilp3232-bit int/long/pointer. Matches 32-bit register width exactly
-O2Balanced optimization. -O3 unrolls too much, overflows 4KB I$
-fno-tree-vectorizeNo SIMD — RV32IMC has no vector unit
-falign-functions=16Aligns functions to 16B cache line boundaries — avoids I$ line splits on jumps
-falign-loops=16Aligns loop headers to cache line boundary — hot loops stay in one I$ line
-falign-jumps=16Aligns jump targets — critical for BTB prediction accuracy

7. Quick Start: Building Software

# Compile with optimized flags
riscv64-unknown-elf-gcc -march=rv32imc -mabi=ilp32 -O2 \
  -T sw/link.ld -nostdlib -nostartfiles \
  sw/crt0.s app.c sw/optimized_lib.c \
  -o app.elf

# Generate hex for simulator loading
riscv64-unknown-elf-objcopy -O verilog app.elf app.hex

# Profile with lunahan_v1 golden model
python3 perf/profile_cpu.py
