1. Philosophy & Origins

XiangShan Methodology

  • Silicon-proven microarchitecture (28nm/14nm tapeouts)
  • 5-stage pipeline discipline with structured stages
  • RISC-V spec-driven design — architecture first, implementation second
  • Gate-first: MLIR verifiers & passes before semantic changes
  • Physical credibility: PPA metrics tied to known-good baselines

pyCircuit Agile Flow

  • Python-native hardware description (V5 cycle-aware DSL)
  • MLIR intermediate representation — multi-level optimization
  • Two-phase tick/transfer simulation model
  • Auto Verilog emission for physical design
  • 3-tier CI gates (G0/G1/G2/G3) for quality enforcement
lunahan_v1 unifies both: XiangShan's battle-tested RISC-V processor methodology implemented through pyCircuit's Python-native agile design flow. The result is a physically-credible RISC-V core that can be designed, verified, and taped out in Python.

2. Architecture Overview

RISC-V RV32IMC — The Sweet Spot

ExtensionSpecDescription
RV32I47 instructionsBase integer ISA — load/store, arithmetic, logical, branch, jump, system
M8 instructionsInteger multiply/divide — MUL, MULH, DIV, REM (hardware Booth multiplier)
C27 instructionsCompressed — 16-bit instruction encoding for code density

5-Stage In-Order Pipeline

PC ──► [IF] ──► [ID] ──► [EX] ──► [MEM] ──► [WB] │ │ │ │ │ Instruction Decode ALU / Data Register Fetch + RegRd Mult/ Memory Writeback (ICache) Divide (DCache) │ │ │ │ │ └────────┴──forwarding paths───────┘ │ │ BTB (64-entry) Hazard Detection Bimodal (stall/flush)
Pipeline FeatureImplementation
Hazard handlingFull forwarding network (EX→EX, MEM→EX, WB→EX) + pipeline stall on load-use
Branch prediction64-entry bimodal BTB, 2-bit saturating counter, mispredict penalty: 2 cycles
Multiplier4-cycle Booth radix-4 multiplier (MUL/MULH/MULHU/MULHSU)
Divider33-cycle restoring divider (DIV/DIVU/REM/REMU)
I-Cache4KB direct-mapped, 16-byte line, single-cycle hit
D-Cache4KB direct-mapped, 16-byte line, write-back, single-cycle hit
Bus interfaceAXI4-Lite (32-bit address, 32-bit data)
Target frequency100 MHz (sky130), target 0.9 IPC

3. Build Flow — Python to GDS

Phase 0 — Prerequisites: Python 3.10+, pyCircuit (pycc), Yosys, OpenROAD, sky130 PDK
Phase 1 — Python → MLIR: python3 rtl/lunahan_core.py → lunahan_core.pyc (MLIR pyc dialect)
Phase 2 — MLIR → Verilog/C++: pycircuit build --target both → Verilog RTL + C++ sim model
Phase 3 — Verilog → GDSII: bash phys/scripts/run_all.sh → Yosys synthesis → OpenROAD P&R → GDS
Phase 4 — Signoff: Timing (STA), DRC, LVS, antenna, power analysis, SPEF/SDF extraction, post-layout gate-level simulation

7. Quick Start

# Clone
git clone https://github.com/wuhannus/lunahan_v1.git
cd lunahan_v1

# One-shot setup & demo
bash scripts/setup.sh

# Generate MLIR
python3 rtl/lunahan_core.py

# Run functional simulation
python3 sim/tb_lunahan.py

# Run physical design flow (requires yosys + openroad + sky130 PDK)
bash phys/scripts/run_all.sh
